Pass criteria (all measured, none assumed): every pinned file matches its SHA-256; the live `/object_info` contains `IPAdapterAdvanced`, `IPAdapterModelLoader`, `CLIPVisionLoader`, `VAELoader` and the option values used; the node pack loads on ComfyUI 0.3.47 (otherwise: report incompatibility, do not patch silently); one 1216x832 image decodes at the requested size; the prompt is `{style prefix} {scene} {style suffix}` of style v1; peak VRAM and runtime recorded; the reference (the supplied Nano Banana painting, labelled provisional external input) visibly influences the output (the same prompt without the reference is rendered once for comparison). A decodable PNG alone is not a PASS and the image is reviewed by the human.
Then (second step, only after the above): a minimal character-reference sheet (front, three-quarter, profile, full body for one provisional character) and three scene keyframes, each with request and model receipts. No LoRA.

## A. Audio dependency tests (stages "audio0" to "audio4"; gated models need the human's Hugging Face access first)
Prepared: `scripts/kaggle/audio_deps_probe.py` (reports which audio packages import and whether CUDA works; downloads nothing, uses no token), unit-tested.
- A0 access and licences (human): Hugging Face access requests accepted for `ai4bharat/indictrans2-indic-indic-1B`, `ai4bharat/IndicF5`, `ai4bharat/indic-conformer-600m-multilingual`; token placed in Kaggle Secrets by the human; each licence read and accepted by the approver; written voice-synthesis permission for the narrator.
- A1 environment: run the probe on Kaggle (Python 3.13 / torch 2.11 as of the LTX runs); list what must be installed; pin versions from each model card; any package that cannot install on this stack is reported as a blocker, not worked around.
- A2 translation (IndicTrans2, `mar_Deva -> hin_Deva`): run the six/seven selected ovis; compare against the assistant draft and the approver's Hindi; record model revision, SHA-256 of the weights, outputs; the approver reviews sacred terms and names. PASS means the model ran and its output was reviewed, never that it is correct by itself.
- A3 ASR (IndicConformer): run on the consenting narrator's own recordings of the reference lines (not on generated audio yet); report CER/WER against the approved text; used later as a check, not as a judge of correctness.
- A4 TTS (IndicF5): BLOCKED until the narrator's Marathi and Hindi reference recordings, transcripts and written permission exist. Then: generate the selected lines, measure durations, re-transcribe with A3, compare with the text; human listening review. Human recordings never count as TTS validation.
- A5 alignment: validate the proposed method (IndicConformer CTC + torchaudio forced alignment) first on synthetic audio with known word times (tone bursts with silences), then on the real generated lines against a hand-checked set of word boundaries; report boundary error in ms; if it does not meet the tolerance the approver sets, it is reported NOT_VALIDATED and subtitles fall back to line-level timing measured from the audio, labelled as such.
- A6 lip-sync (MuseTalk 1.5): only if the approved selection contains Bankatlal's question (ovi 109) as a close enough speaking shot; first an environment test (does it install on the Kaggle stack at all), then one painted-face trial; unsuitable means NOT_VALIDATED.
