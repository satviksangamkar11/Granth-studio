## 2. The fixed pipeline, in order

**Common rule:** each stage writes an immutable receipt containing input hashes, tool version, output hashes, validation result and owner approval reference. A rerun skips a verified result; a changed input invalidates only its dependents. Failed or unknown paid requests stop at reconciliation. The paths below under `canon/adhyay_NN/` are the **proposed standard layout**; today’s A1 files retain their existing paths until migrated and checked.

## 3. Libraries that survive every Adhyay

- **Presets:** `assets/v5_presets/index.json` and its 11 JSON recipes already exist. Store immutable version, SHA-256, required roles, compatible image type and demonstrated render receipt. A new preset is **JSON parameters within Builder v2’s supported schema**, proposed by Kimi only after `NEED_NEW`, test-rendered and owner-approved. A real renderer gap is a separate owner decision; it cannot be disguised as a preset.
- **Shot plans:** use one file per scene, for example `canon/shot_plans/A1/S4.json`, containing ordered shots with ovi/beat IDs, one-line visible action and held pose, preset ID/hash, image role→ID/hash, transition, approved staging, source/script/timing fingerprints, `approved_by`, date and receipts. Keep old versions. Exact fingerprints permit automatic replay. For a different scene or chapter, show a candidate by explicit beat/pose/framing tags; code verifies compatibility and the **owner approves the adaptation**. A tag match never transfers a factual claim or prior approval.
- **Character, place, prop and image catalog:** `canon/series/entities.json` plus chapter `images/catalog.json`. Stable identity and versioned chapter state prevent costume or age drift; local approved reference sheets and exact hashes remain authoritative even if Flow’s saved assets disappear. An image ID resolves to exactly one approved file version.
- **Reusable effects pack:** `canon/series/sounds/palette.json` and hashed audio files. Start from the existing 22 proposed sounds and 18 A1 cue suggestions in `scripts/source/a1_audio_spec.py:87–130`; they are **not yet sourced audio**. Each accepted entry needs ID (`bed_*` or `fx_*`), kind, ElevenLabs prompt/model/settings, duration, WAV hash, credit receipt, rights status and owner approval. Generate a sound once via the ElevenLabs ledger, then reuse it. Stage 1 suggests cue IDs; Stage 2 may select among approved cues; code anchors them to a measured line or picture event. Default: no distinct effect over speech; a quiet bed or ducked exception needs owner-approved levels and a test against **both** language tracks. Measure the finished mix: the existing `-22 dBFS` active-speech setting and `-1 dBFS` peak history do not establish delivered loudness.
- **Voices and glossary:** `canon/series/voices.json` preserves approved speaker IDs, language, model and test clip; `canon/series/glossary.json` preserves spellings, pronunciation and source. The A1 voice map and packet glossaries seed these files. Changes create new versions and invalidate affected clips; only the owner approves them.

## 4. What must become “no new code”

A chapter supplies data: `canon/adhyay_NN/chapter.json`, `source/ovis.jsonl`, `research/packet.json`, `split/edits.json`, `script/easy.json`, `bible/entities.json`, and owner-approved additions to `images/catalog.json`. Generated files such as measured audio, briefs, cues and shot plans are outputs, not handwritten Python. `chapter.json` selects paths and versions; it contains no executable code.

Build one chapter-neutral CLI with one command per stage: `granthstudio pilot source|stage1|script|voice|timing|images|stage2|render|master|verify --adhyay N`. **These commands are a required interface, not commands that exist today.** Preserve the working A1 scripts as compatibility wrappers while their behavior is moved and verified. In particular, move `a1_audio_spec.py` lines/cues/captions, `build_shot_jobs.py` character/place/prompt rules, `build_final_set.py` selections, `wm_clean_v2.py` learning image and `BIG_ON`/clone lists, voice paths, timing defaults and renderer asset mapping into validated data. Keep safe defaults in code; refuse a missing chapter configuration.

The freeze test has two parts: a synthetic chapter using different scene counts and IDs passes all stage validators **before A1 is declared complete**; then the real Adhyay 2 source, briefs, images and audio run with **zero code diff**. Any discovered gap before that freeze is fixed in the common harness, reviewed by Codex and retested on A1.

## 6. Owner decisions and recommendations

1. **Kimi and presets:** approve Kimi drafting *schema-limited preset JSON and shot-plan JSON only*. It cannot write Blender or animation Python. Test and owner-approve each new version.
2. **Preset 03 variants:** allow a small, bounded JSON set for push in/out, pan left/right and starting frame **only after** each variant renders correctly and looks good. This addresses repetition without opening Builder v2.
3. **Layers:** start with the 59 flat finals. Approve a cut-out or extra pose only when a specific beat cannot be shown faithfully with a suitable flat image.
4. **Image briefs and IDs:** Kimi Stage 1 supplies beat, pose and reason; code builds the Flow prompt from approved canon; owner accepts the image and hash. Stage 2 selects IDs only. A missing image returns `NEED_NEW`.
5. **Hindi:** measure every accepted Hindi clip and use it in the shared beat even while translation quality remains `NOT_VALIDATED` under the owner’s no-per-line-review ruling. Decide whether that status is acceptable for release.
6. **Delivery:** approve one multistream master with selectable subtitles and a language-neutral `1878` caption; test intended players. Make platform copies only if switching is unsupported.
7. **Effects and rights:** use ElevenLabs for an approved reusable effects pack, with no ElevenLabs music. Confirm credits, sound-use terms and the permitted Flow watermark-free export/use route before production.
8. **S4:** approve its source, images and three staging choices before saving a reusable record. Its previous `VALID` Kimi run and Nemotron `PASS` do not supply that approval.

## 7. Remaining risks and decisive tests

Opus is right that S4 can prove the path cheaply and that the Kimi **input contract** caused its invented images. I disagree with deferring all reusable matching until A2: exact replay plus a small, explicit template-candidate mechanism must be built before the claimed freeze. It can remain simple; fuzzy similarity and predicted hit rates are unnecessary. I also disagree that five flat pushes alone would prove the whole architecture: S4 proves binding, bilingual assembly and recovery, while at least one genuinely layered or changed-pose case must prove the library’s limits and `NEED_NEW` gate before A1 closes.

A1’s 59-shot budget covers 52 core lines, not an unexamined promise to include all 62. Test the owner’s inclusion choice against measured clips. Test scene-level source coverage, continuity, visible bow/gesture truthfulness and both subtitle languages with the owner. Test a changed image hash, changed script, changed voice clip, missing layer, wrong catalog ID, interrupted paid request, killed render child and unsupported player; each must fail closed or resume from a verified receipt. Measure actual CPU/GPU use, render time and free disk during S4 and the full run; the recorded 117–201 seconds per shot is study evidence, not a production guarantee.

The strongest final acceptance test is practical: complete and approve A1, then start A2 with its own source and chapter data while Git shows **no application-code change**. Until that succeeds, “fixed pipeline” remains a design goal, not a demonstrated result.
