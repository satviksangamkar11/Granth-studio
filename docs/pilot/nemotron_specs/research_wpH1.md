# SPEC H1: NEW `research/pieces/h1_compile_teacher.py` + NEW `research/pieces/test_h1_compile_teacher.py`: compile the REAL video-review evidence into the Kimi teacher (playbook + technique catalog)

GOAL: a "teacher for Kimi" with two stages. Stage 1 = film direction (shot choices, composition, camera, character performance, image briefs, justified sound). Stage 2 = animation selection (which EXISTING presets / pose arrangements execute a shot, `NEED_NEW` when something is missing; never invent a preset). The full video analysis already produced per-group review reports; this module compiles them. Pure logic: every model call goes through an injected function `ask(prompt: str) -> str`. No network in tests. No Kimi.

INPUT (existing files): `<output_dir>/<video_folder>/api_log.json`, a dict `{group_id: {"status": "COMPLETE"|"PENDING", "report": {...}}}`. A COMPLETE report dict has these keys: video_id, scene_id, start_frame, end_frame, start_time, end_time, characters, observed_animation, inferred_technique, camera_motion, character_motion, visual_effects, required_assets, potential_blender_implementation, granthstudio_capability (one of V2_REUSE, V2_EXTENSION, V3_ACTION, NEW_ARTWORK, UNKNOWN), evidence_frames (list of ints), confidence (LOW|MEDIUM|HIGH), uncertainties. group ids start with `shot_`, `event_` or `pilot_`. Many fields are the string "UNKNOWN".

FUNCTIONS (all public, plain dicts, one return shape each):
1. `load_reports(output_dir)` -> list of report dicts, each with added keys `group_id` and `kind` ("shot"|"event"|"pilot"), COMPLETE only, stable order (video folder name, then natural order of group_id). A corrupt api_log.json raises ValueError naming the file (never silently skipped).
2. `video_digest_prompt(video_id, reports, max_chars=24000)` -> str. Builds a compact evidence table for ONE video: one line per report whose inferred_technique is not "UNKNOWN" or whose observed_animation is not UNKNOWN-like, formatted `[group_id t=<start_time>-<end_time>s frames=<evidence_frames>] observed: ... | technique: ... | camera: ... | character: ... | effects: ... | assets: ... | capability: ... | conf: ...`. Drops lines with confidence LOW and observed text that says nothing is visible (black frame) unless nothing else exists. Truncates the table at max_chars (keep earliest lines, append `[truncated: N more lines]`). The prompt asks the model for ONE JSON object `{"video_id": ..., "techniques": [{"name","observed","evidence":[{"group_id","frames","time"}],"camera","character_performance","effects","required_artwork","capability_class","when_it_works","when_not_to_use","confidence"}], "pacing_notes": str, "audio_note": "NOT_ANALYZED"}`; it MUST say: use only the table, cite group ids and frames for every technique, write UNKNOWN instead of guessing, never infer editing software, lenses, hidden rigs, or screenplay text, and creative intention is a hypothesis.
3. `parse_json_reply(text)` -> dict or None: extracts the first JSON object from a reply (strip code fences, leading prose); returns None if it does not parse or is not a dict.
4. `cross_video_prompt(digests)` -> str. `digests` = list of per-video digest dicts. Asks for ONE JSON object `{"recipes": [{"name","stage1_lesson","stage2_lesson","required_artwork","capability_class","videos":[video ids],"evidence":[{"video_id","group_id","frames"}],"counterexample","when_not_to_use","confidence"}], "gaps": [str]}`. Rules in the prompt: merge the same technique across videos but KEEP every source reference; a lesson supported by one video stays single-source; Stage 2 lessons may only mention existing presets/assets in general terms and must use NEED_NEW (with the missing image/pose/renderer capability stated) when the capability class is NEW_ARTWORK or V3_ACTION; never invent a preset id; reference music/dialogue is research only; Kimi gets no new permissions (no rewriting EASY wording, no invented story events or dialogue, no timings, no music in production).
5. `classify_recipe(recipe)` -> "GENERAL" if len(set(videos)) >= 3, "STYLE_SPECIFIC" if exactly 2, else "EXPERIMENTAL". `usage_bucket(recipe)` -> "USABLE_NOW" if classification != EXPERIMENTAL and capability_class in ("V2_REUSE","V2_EXTENSION"); "USEFUL_BUT_BLOCKED" if classification != EXPERIMENTAL and capability_class in ("NEW_ARTWORK","V3_ACTION"); else "RESEARCH_ONLY".
6. `compile_teacher(output_dir, ask, workers=9)` -> dict `{"playbook_md": str, "techniques": dict, "failed_videos": [video ids], "stats": {"reports": n, "videos": n, "recipes": n}}`. Steps: load_reports; group by video_id; for each video call `ask(video_digest_prompt(...))` in a ThreadPoolExecutor(workers); parse with parse_json_reply, retry ONCE with the same prompt if it does not parse, else add the video to failed_videos and continue; then one `ask(cross_video_prompt(digests))` (retry once); drop recipes without evidence entries; add classification and usage_bucket to each recipe. `playbook_md` is Markdown with these sections in this order: `# Kimi animation teacher (read-only research hints; canon, schema and owner approvals always win)`, `## How to use`, `## Stage 1: direction lessons` (recipes with bucket USABLE_NOW or USEFUL_BUT_BLOCKED, each with name, lesson, evidence references like `video <id> frames [..]`, when not to use, confidence, classification), `## Stage 2: execution lessons` (USABLE_NOW recipes with required artwork; USEFUL_BUT_BLOCKED recipes marked `NEED_NEW: <missing capability>`), `## Research only` (EXPERIMENTAL), `## Sound` (must state: audio was only checked for silence; narration, SFX and music are NOT analyzed in this run, so no sound lesson is claimed), `## Gaps and uncertainties`. The techniques dict is `{"schema": 1, "recipes": [...], "gaps": [...], "failed_videos": [...]}`.
7. `write_outputs(output_dir, result)` writes `KIMI_ANIMATION_PLAYBOOK.md` and `MASTER_TECHNIQUES.json` key `_teacher` (merge into the existing JSON object, preserving all other keys; a corrupt existing file raises ValueError) into output_dir. Backs up each existing file first as `<name>.bak_before_teacher`. Atomic tmp+replace, utf-8.
8. `main(argv=None, ask=None)`: `--output` (required), `--workers` (default 9), `--dry-run` (prints stats only: report count per video, no ask calls). If ask is None, build it from `nvidia_scheduler.NvidiaScheduler` (add `<repo_parent>/animation_research_tool` to sys.path inside this default branch only; keys come from the scheduler's own .env loading; model `nvidia/nemotron-3-ultra-550b-a55b`, `read_timeout=900`, `max_calls=60`, thinking off via a post wrapper that adds chat_template_kwargs {"enable_thinking": false}; return the reply text or "" on failure). Prints one JSON object with the stats and exits 0 if failed_videos is empty else 1.

TESTS (unittest/pytest, tmp dirs, fake `ask`; no network, no real model): load_reports (complete only, kind, order, corrupt file ValueError); video_digest_prompt drops LOW/UNKNOWN lines, truncates, includes group ids and frames; parse_json_reply with fences/prose/garbage; classify_recipe thresholds (1,2,3 videos); usage_bucket truth table including NEW_ARTWORK -> USEFUL_BUT_BLOCKED and EXPERIMENTAL -> RESEARCH_ONLY; compile_teacher with a fake ask returning valid JSON (playbook has the 6 sections in order, a recipe without evidence is dropped, every recipe keeps all video references), a video whose reply is invalid twice lands in failed_videos while others succeed, a retry that succeeds on the second call; write_outputs backup + merge preserving other keys + corrupt JSON ValueError; main --dry-run makes zero ask calls; the Sound section states audio is not analyzed.
