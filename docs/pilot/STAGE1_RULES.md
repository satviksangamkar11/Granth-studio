## 1. Purpose
Stage 1 plans the EXACT STORY and the IMPORTANT TEACHINGS of a chapter around the owner's locked EASY script. A chapter may have little story and much philosophy (even zero stories): Stage 1 must still cover it honestly. Kimi runs at HIGH effort. The existing "directors" of D-018 are the roles inside Stage 1:

## 2. Story vs philosophy
- Every ovi gets ONE primary type: STORY, TEACHING, PHILOSOPHY, INVOCATION, RECAP, PHALASHRUTI, OTHER (PHILOSOPHY is an addition to D-018's list; recorded as a contract amendment).
- Type does NOT decide omission. Film source-supported story events, never invent connecting events or closure. Keep the teachings the script, the owner's notes or the story's meaning require. Sustained discourse is shown as narration over approved typography (composited later, never generated inside illustration art), source-named symbols and contemplative holds. NEVER an invented scene or conversation; never fake Maharaj dialogue to animate philosophy.
- Every ovi gets exactly one disposition: VISUALISED | NARRATED | QUOTED | MERGED_EQUIVALENT (names the covering line/ovi) | PROPOSE_OMISSION (with reason). Only the OWNER approves an omission. A1 evidence: ovis 138-142 (the teaching) are all kept; the unfilmed ranges 1-32, 33-38, 39-57, 58-69, 106-107, 145-146 are decided in `canon/story_split_edits/A1_rev1.json`.
- If required coverage is missing from the script, code reports the gap to the owner; Kimi never drafts replacement wording and never critiques the script.

## 3. Calls (HIGH effort, no automatic paid repair, one call each)
1. Chapter map: whole chapter -> story_map (types, events, closure, teachings).
2. Episode/coverage plan: map + locked script -> coverage, scene order, section kind (story | discourse).
3. Per-scene direction packet (one call per scene or small group): scene card -> shots -> image briefs -> canon looks -> voice assignments -> sound suggestions -> questions.
4. Code consolidates, validates, checks chapter-wide consistency; Nemotron cross-checks (advisory); owner approves.
Existing script ids and order are immutable: if a scene grouping conflicts with the script headings, report it, never renumber.

### Voice casting detail
Voice casting rule (owner 2026-10-28): when Kimi Stage 1 casts voices it receives the VOICE LIBRARY: the data of ALL saved voices with a DESCRIPTION for each (`canon/series/voices.json`: voice_key, voice_id, name, gender, age feel, tone/character description, Marathi and Hindi verified flags, which character currently uses it). Kimi chooses the voice for each speaking character BASED ON THOSE DESCRIPTIONS and writes a short reason. A RECURRING character always keeps the SAME voice in every Adhyay (taken from the library assignment, never re-chosen); a new character gets the best-matching UNASSIGNED voice; if no saved voice fits, Kimi raises a question to the owner (it never invents a voice id). Today the library holds only the four cast voices with one-line notes (`canon/audio/A1_eleven_voices.json`) and the female voices (Mugdha, Roopa, Radha K, Kalyani, Mukta) exist only as names in the decision log: a Nemotron-written tool fetches the owner's saved voices and their descriptions from the ElevenLabs account (list-voices call, no credits; the key is read at run time) and builds the library; the owner can edit the descriptions.

## 8. Sound (researched by Codex with the official ElevenLabs docs on 2026-10-28: `CODEX_ELEVENLABS_SOUND.md`)
- Kimi Stage 1 PLANS sound from the supplied, versioned sound palette (`canon/series/sounds/palette.json`): it picks an AVAILABLE sound id (+version) or emits NEED_NEW with a SOUND-EFFECT PROMPT (an ElevenLabs-ready description of the audible source, material, action, distance, environment, intensity), purpose, source/STAGING basis and symbolic anchor. That prompt is "the script for ElevenLabs" Kimi writes; the speech script stays the owner's. Kimi writes no timings and no paid-call settings (duration, loop, influence are applied by code).
- METHOD: separate ElevenLabs Sound Effects files (`POST /v1/sound-generation`; 0.5-30 s; prompt_influence 0-1; loop supported; model eleven_text_to_sound_v2), mixed by our code. NOT tags inside the speech script: tags can produce effects ([footsteps], [door creaking], [thunder rumbling]) and both eleven_v3 and eleven_v4 accept them, but placement is not guaranteed, they are tied to each language's speech file, and a change needs speech regeneration. Reconsider only after an owner-approved bilingual test. Vocal direction tags need a separate owner decision.
- Reuse first. Otherwise code generates ONCE through the credit ledger (dedupe by prompt+model+settings+format hash; reserve, submit, decode, hash, keep candidate + receipt), the owner listens, then it becomes AVAILABLE with hash and rights note. Uncertain result: stop and reconcile.
- Rules: nothing over speech without ducking; no ElevenLabs music (film use excluded on Starter); no invented events/ceremonies/crowds/miracles; no automatic blessing chime, halo sound or transition whoosh; silence is valid; camera/animation presets trigger no sound automatically; teaching/reaction = silence or quiet bed.
- Defaults (start map from the 18 cues of `a1_audio_spec.py`): roadside establishes/holds `bed_roadside_quiet`; feast `bed_courtyard_feast_murmur`; noon `bed_village_noon_heat`; leaf plates `fx_leaf_plate_rustle`; walking `fx_footsteps_road_dust`; bow `fx_cloth_bow_rustle`; plate `fx_plate_set_down`; birds `fx_birds_flutter_to_trees`; door `fx_door_wood_creak` (staging); cattle `fx_cattle_distant`; drinking `fx_water_trough_drink`; pot `fx_brass_pot_clink` (staging); departure `fx_wind_rush_run` (listen: no supernatural whoosh). Nine other proposals stay NEED_NEW until needed.
- Mix: code anchors cues to measured lines ("after line" = after BOTH languages' windows); overlapping effects duck against the UNION of both speech windows (proposed 12 dB, 100 ms attack, 300 ms release; owner listening approval pending). Both videos share the same effects and picture.
- Rights (official terms): sound effects terms expressly permit incorporation into films; standalone/sound-library distribution is prohibited, so the pack stays private; the commercial licence of material made during a paid plan survives cancelling, but ONLINE availability is not guaranteed: download and keep every file and receipt.
- Cost (conflicting official figures; reconcile actual charges): about 40 credits/second when a duration is set, or about 200 credits per generation. A 25-sound pack is about 5,000-14,000 credits; a later chapter with two new 3 s effects is about 240 credits; a fully reused chapter costs 0 SFX credits. Starter = 30,000 credits/month shared with speech.

## 9. Image briefs: the Adhyay 1 lessons inside the prompt
Approved flat-colour style (steady navy outlines, light hatching, warm palette, filled depth), one style anchor; full chapter-state identity (age/build, face/hair, exact costume) with the accepted sheet; exactly the visible people, each once, with position, ONE action and gaze target; accepted place + fixed features; critical prop and its state/material; framing, angle, foreground, subject size and screen directions across adjoining cuts; preset slot, full-frame/layer need, safe crop, room for camera move/caption; approved light; ONLY on-screen facts (no narration, bracketed commentary, literalised comparisons); exclude extra people, text, letters, inset frames, borders, modern objects; references = visible characters, mandatory place, one style anchor, central prop (+ at most 1-2 neighbours for a continuity fix); no hand side unless source/direction/continuity requires it; rewrite a regeneration prompt completely; no seed assumptions. For Maharaj (A1): accepted adult-youth identity, cropped hair, OPEN frayed grey-white vest, short white hip cloth. CODE builds the final Flow prompt from the approved briefs + series blocks (`IMAGE_PROMPT_RULES.md`). Haiku agents (LOW effort) execute exactly (README section 9).

## 10. Must NOT
Kimi never writes/edits/translates/critiques the EASY script, writes no timings or hashes or approvals, invents no events/dialogue/closure, makes no images or voices, writes no code, invents no preset or image id, redecides no known cast/place/style, and gets no automatic paid retry.
