# GranthStudio: ONE fixed pipeline for ALL Adhyayas (proposal for the owner's approval, 2026-10-26)

The owner's instruction: fix the WHOLE pipeline flow (not only Google Flow) so that every Adhyay (up to 21) goes through the same steps, with no re-deciding. Adhyay 1 is the reference run: whatever works there is frozen here as the template; mistakes found there are written into `docs/pilot/DECISION_LOG.md` and fixed once. Every film = one or two Adhyayas (`N`).

## 1. Two kinds of assets (this is the heart of the design)
**SERIES-LEVEL assets: built once, only grown, reused by every Adhyay**
- Art style: the style paragraph + the owner's reference clips (`assets/pilot_refs/style_v2/`), "FULL frame" rule.
- Character registry: permanent id, identity paragraph, saved reference sheets (hashed), voice ids (Marathi and Hindi), age/costume states per Adhyay. Recurring characters (Gajanan Maharaj, Bankatlal, Damodarpant, Devidas, ...) are made ONCE.
- Places and props library (village, road, well, ...) with reference sheets.
- Preset library (`assets/v5_presets/`, JSON; grows when a shot needs NEED_NEW; owner-approved, versioned).
- Sound library: closed palette; each generated sound stored once with its hash and prompt, reused across Adhyayas.
- Voices: the voice map (`canon/audio/*_voices.json`), the loudness setting (-22 dBFS rms), model (`eleven_v4`).
- Rules: the director contract (T1-T8), validators, ledgers (Kimi, ElevenLabs), decision log.

**PER-ADHYAY assets: made again for each N**
Source text and frozen answers, story split, easy script, audio plan, voice clips, measured timing, bible slice, image list, director output, shot images, renders, sound cues, mixed tracks, approvals.

## 3. What makes it fixed (so nothing is decided twice)
- One standard folder per Adhyay: `canon/adhyay_NN/{source,split,script,audio,bible,images,director,render}` plus the series-level `canon/series/{style,characters,places,presets,sounds,voices}`. Today the files are named `A1_*` and some live in the repo root of `canon/`; moving to this layout is part of the generalisation step below.
- One command per stage, one parameter `--adhyay N` (today the scripts have Adhyay 1 baked in).
- Each stage writes a receipt (input hashes); a changed input makes later approvals STALE (already how the manifest works).
- Voice ids, loudness, model, style and presets never change between Adhyayas unless the owner records a decision.

## 4. Generalisation work (free, code only; do it ONCE after Adhyay 1 is accepted, before Adhyay 2)
Counts of Adhyay-1 hard-coding found today: `story_split.py` 21, `director_test.py` 24, `a1_audio.py` 9, `a1_audio_spec.py` 2 (the lines are Adhyay 1 DATA in Python), `a1_eleven.py` 12, `a1_voice.py` 19, `a1_eval.py` 5, `a1_bible.py` 9, `easy_script.py` 2, `director_run.py` 3.
1. Move the line/cue/caption DATA out of Python into per-Adhyay data files (`audio_spec.json`); keep the code Adhyay-neutral.
2. Rename `a1_*` to neutral names and take `--adhyay N` (paths derived from N); keep thin wrappers so old commands still work.
3. Series registry files for characters, voices, places, sounds (voice ids come from the registry, not from a per-run map).
4. Per-Adhyay evaluation expectations (`eval/expected_NN.json`) generated from the dialogue table and the script.
5. Tests parametrised over Adhyays using synthetic fixtures plus Adhyay 1 real data.
6. A `new_adhyay.py N` command that creates the folder skeleton, checklist and the decision-log header.

## 5. Estimated effort per Adhyay after Adhyay 1 (a forecast, not a measurement)
- Kimi: planner about $0.14 + director about $0.2-0.4 (more if more shots); ElevenLabs: about 4,000 credits for speech + only NEW sound effects; so the 30,000-credit Starter month covers one or two Adhyayas.
- Owner time: the easy script, listening, new reference sheets (drops sharply once recurring characters are saved), and one tailored image per shot (no limit; this stays the biggest block).
- Library growth: presets and sounds should mostly be reused from Adhyay 3-5 on; images less so (new places and poses). Track the reuse rate per Adhyay in the log.

## 6. Risks and how this plan handles them
- Continuity across Adhyayas (a character ages, a costume changes): the registry stores a STATE per Adhyay; the director and image list read that state.
- Drift in saved references (Flow) or voices (ElevenLabs model updates): keep local copies of every accepted reference and clip with hashes; record model/version in the receipt.
- Cost creep: caps per ledger, per-stage estimates before spending, owner approval for each raise.
- Rework after approval: stages are ordered so cheap, reversible work comes first and the owner's image hours come last.

## 8. Image stage as proven on Adhyay 1 (2026-10-27; do the same for every Adhyay)

Job files from the catalog (`build_shot_jobs.py`): characters as @ chips, place sheet, 3 style images, short prompt that already contains the strict character sentence (Maharaj: slim adult, cropped hair, open vest, short hip cloth). 3. Review: Haiku checks every picture, Claude views contact sheets, Codex reviews read-only per sheet; fix list = A real defects / B minor / C story questions (a read-only agent checks the script, then the web). 5. Fix pass: EDIT first (Flow edit page, download immediately after the edit), regenerate only for identity/age/framing. 6. Final set `final/` + list + hashes. 7. Clean set `final_clean/` (sparkle removal, corner check). 8. Folder audit (`audit_flow_outputs.py`). 9. Decision log + lessons. Layers (for layered presets) are decided shot by shot AFTER the proof render: flat image first, cut layers from the final only where depth is needed.
